**主题**: 解决大模型（LLM）输出JSON格式异常导致的线上事故
## 一、 核心问题分析

**根本原因**:

大模型本质上是一个 **“预测下一个Token”的概率系统**，而非严格的指令执行系统。

- 它不知道JSON的语法规则，只是根据语料概率（如“{”后大概率接“"name"”）进行生成。
- 99%的情况下概率符合语法，但剩下的1%随机性会导致生产环境频繁崩溃。

## 二、 大模型输出的“八类违规操作”

在要求严格返回JSON Schema时，模型常犯的错误类型：
1. **礼貌性自杀**
    - **现象**: 在JSON前加客套话，如“好的，根据您的要求...”。
    - **后果**: `json.loads` 直接报错。
2. **Markdown强迫症**
    - **现象**: 即使未要求，也强行用 ```json ... ``` 包裹内容。
    - **后果**: 破坏解析逻辑。
3. **薛定谔的类型系统**
    - **现象**: 字段类型随机跳变（数字变字符串、null变汉字“暂无”）。
    - **后果**: 后端代码处理崩溃。
4. **截断式崩溃**
    - **现象**: Token耗尽导致输出中断（如断在冒号后），结构残缺。
    - **后果**: 难以修复的结构性错误。
5. **幻觉式补全**
    - **现象**: 提取内容数量不足时，自动编造虚假数据凑数。
    - **后果**: 数据内容错误（数量对，内容假）。
6. **单双引号混用**
    - **现象**: 使用单引号 `'` 包裹键或值。
    - **后果**: 不符合标准JSON规范，解析报错。
7. **尾随逗号 (Trailing Comma)**
    - **现象**: 列表/对象最后一个元素后多加逗号。
    - **后果**: Python字典允许，但标准JSON不允许。
8. **未转义字符**
    - **现象**: 字符串中直接包含换行符、制表符或反斜杠。
    - **后果**: 解析器无法处理。

## 三、 六层防御体系解决方案

通过构建防御体系，将解析成功率从 **95% 提升至 99.9%**。

| **层级** | **名称**       | **核心逻辑**                                                            | **作用**             |
| ------ | ------------ | ------------------------------------------------------------------- | ------------------ |
| **L1** | **Prompt工程** | • 给出Few-shot正反例<br>• 明确禁止客套话/Markdown<br>• 嵌入详细JSON Schema          | 降低出错概率 (5% -> 1%)  |
| **L2** | **输出清洗**     | • 正则去除首尾客套话<br>• 剥离Markdown标记<br>• 去除BOM头和空白字符                      | 处理简单的包装格式问题        |
| **L3** | **智能修复**     | • 使用 `json.repair` 等库<br>• 启发式修复：替换引号、删尾随逗号、补全括号                    | **核心防御**，挽救90%残次品  |
| **L4** | **Schema校验** | • 使用 Pydantic / JSON Schema<br>• 强类型校验、枚举检查、缺失字段检测                  | 确保业务数据正确性          |
| **L5** | **自修复循环**    | • 将错误信息回传给模型，要求其“自我修正”<br>• 设置重试上限 (2次)                             | 兜底机制，救回80%失败请求     |
| **L6** | **约束解码**     | • **(终极方案)** 在推理阶段屏蔽非法Token<br>• 仅适用于自部署 (vLLM等) 或特定API (JSON Mode) | 从根源杜绝语法错误 (100%正确) |

## 四、 总结

1. **工程化门槛**: AI应用的真正门槛不是让模型“做到”，而是让它 **“稳定地做到”**。
2. **修复哲学**: 面对错误，不是重新生成（成本高），而是 **“就地抢救”**（清洗+修复）。
3. **价值体现**: 处理字符串清洗、边界情况防御这些“脏活累活”，是决定AI产品能否扛住真实流量的关键。
